# BtcTrendV4 · 策略说明

在 V3（现货、只做多、最高 1x）基础上加了两件东西：**做空**和**条件化倍率**。
读这份文档前请先接受一个算术事实，它决定了后面所有的设计：

> 全额保证金下，强平距离 = 1/倍率 − 维持保证金率（BTC 约 0.4%）。
> 强平时损失 = 倍率 × 该距离 ≈ 100% 本金。
> **所以「倍率」不是收益参数，是爆仓价参数。40x 意味着价格反向走 2.1% 就结束。**

---

## 一、规则

### 1. 方向信号（与 V3 相同）

```
z = 平均( 20/40/60/90 日归一化动量 )，各自按波动率标准化，截断在 ±3
```

- `z > 0.20` → 做多，权重 `min(1, 40%/年化波动) × z`
- `z < −0.20` 且**资金费达标** → 做空，权重同上
- `z` 回到 0 → 平仓

次日开盘成交，不做日内。

### 2. 做空的资金费门（新增，这是本轮唯一真正的改进）

做空只允许在资金费处于**过去一年 40 分位以上**时进行。

```
gate = 当日资金费 > rolling(365d, min 120d).quantile(40%)
```

滚动窗口，不用全样本，所以没有前视。

依据：2020-2026 年，处于门内的空头日（301 天）胜率 54.5%、日均 +14.9bp、累计 +44.8%；
被门挡掉的日子（512 天）胜率 46.1%、日均 −11.6bp、累计 −59.2%，7 年里有 6 年亏钱。

直觉：资金费为负 = 空头已经拥挤 = 这时去做空是接最后一棒，还要倒付资金费。

**不要给多头加同样的门。** 我测过：只有资金费低时才做多，年化从 74.5% 掉到 1.8%（Sharpe 0.27）。
高资金费往往就是主升浪，躲开它等于躲开全部收益。

### 3. 倍率阶梯（新增）

| 档位 | 条件 | 倍率 |
|---|---|---:|
| 顺势低波 | `z>0.2` 且 `σ<45%` 且 距一年高点 `<10%` | **1.75x** |
| 正常 | `σ<60%` 且 距一年高点 `<20%` | **1.25x** |
| 默认 | 其余 | **1.00x** |

σ = 60 日年化波动；距离用收盘价对 365 日最高收盘价。

三档都对应一条硬约束：`LEV_MAX = 3.0`。代码里没有任何路径能让倍率超过 3。

### 4. 没有止损

`stoploss = -0.99`，即不设。理由是这套策略的全部利润来自右尾（前 5 笔贡献超过 100% 的利润），
加止损会把它砍掉。回撤控制靠倍率，不靠止损。

## 二、为什么不是 40x

我在 1x 到 40x 全区间跑了一遍，含逐日强平判定：

| | 结果 |
|---|---|
| 1x–5x | Sharpe 恒定 1.24–1.25，年化 34.5% → 120.9%，回撤 −24.4% → −83.5% |
| 8x | 2021-09-07 强平，权益 37.22 → 0 |
| 20x | 2020-06-02 强平 |
| 40x | 2020-05-10 强平，只活了 4 个月（当时已赚 115%） |

两个更根本的原因：

1. **倍率越高，爆仓距离越近。** 40x 是 2.1%，而 BTC 有 **37.6% 的交易日**出现过 ≥2.1% 的日内逆向波动。连续挂 10 天不被打到的概率是 **0.9%**。
2. **低波动 ≠ 低风险。** 用「波动率倒数」定倍率，规则会在 σ<30% 时给到 1.7x——而那个区间是唯一年化亏钱的（−47%）。币圈的低波动常常是顶部。

要规则算出 40x，需要年化波动降到 2.5%。**过去 7 年 BTC 的 60 日波动最低 26%，中位 54%。**

---

## 三、倍率应该怎么选

按你能承受的回撤倒推，而不是按想要的收益：

| 你接受的最大回撤 | 用这个倍率 | 样本内年化 |
|---:|---:|---:|
| −25% | 1.0x | 34.5% |
| −30% | 1.25x | 43.3% |
| −35% | 1.5x | 52.0% |
| −45% | 2.0x | 68.8% |
| −55% | 2.5x | 84.3% |
| 不接受回撤 | 不要跑这个策略 | — |

默认的阶梯配置落在 1.0–1.75x，平均 1.15x，样本内年化 45.9%、回撤 −26.7%、Sharpe 1.26。

## 四、实现与运行

策略文件：`crypto-spot-kit/user_data/strategies/BtcTrendV4.py`
配置：`config.btc-trend-v4.json`（futures / isolated / can_short）
资金费数据：`crypto-spot-kit/user_data/funding_daily.csv`（策略启动时读取，缺失则关闭空头门并告警）

```
# 回测（需要能访问币安合约市场元数据）
python -m freqtrade backtesting --config config.btc-trend-v4.json \
  --config config.v4-futures-data.json --userdir user_data \
  --strategy BtcTrendV4 --timeframe 1d --timerange 20200101-20261031

# 模拟盘
python -m freqtrade trade --config config.btc-trend-v4.json \
  --config config.v4-futures-data.json --userdir user_data --strategy BtcTrendV4
```

### 两个必须知道的实现细节

1. **freqtrade 不模拟强平。** 在 8x 以上它会给出一条漂亮的上行曲线，而真实账户已经归零。
   本文所有结论来自自建引擎（`strategy/lev.py`），强平按盘中高低点逐日判定。
   这也是我坚持把 `LEV_MAX` 写死在代码里的原因。
2. **资金费门依赖本地 CSV。** 回测和模拟盘读 `funding_daily.csv`；实盘应改成调交易所的
   fundingRate 接口（`/fapi/v1/fundingRate`），否则门不会更新。

## 五、上线前的检查清单

- [ ] 先跑 8–12 周模拟盘，核对成交价与回测偏差在 0.3% 以内
- [ ] 确认资金费门的数据源在实盘是实时的（不是读 CSV）
- [ ] 确认账户是**全仓**且只跑这一个策略；同时跑别的策略会让「名义敞口/权益」失真
- [ ] 首期投入 ≤ 20% 资金，倍率先用 1.0x 跑完一轮完整交易再考虑上调
- [ ] 记录每次调仓的实际倍率，与阶梯输出比对，确认没有静默失效
